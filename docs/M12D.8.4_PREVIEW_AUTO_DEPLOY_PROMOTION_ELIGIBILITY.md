# M12D.8.4 — Preview Auto-Deploy Re-enable + SHA-Bound Promotion Eligibility Gate

## Objective

Turn the M12D.8.3 revision-aware Preview regression result into a reusable promotion decision bound to the exact deployed Git SHA, while keeping Production deployment fully manual and out of scope.

## Eligibility contract

A Git revision is promotion-eligible only when all of these are true:

1. Coolify deployed that exact revision to the dedicated Preview resource.
2. The post-deploy `preview-deployed` repository dispatch identified the same full `deployed_sha`.
3. The dispatch branch equals `fix/m12d8-reconcile-056-ui`.
4. The gate profile is `full`.
5. `/healthz` and `/readyz` are stable for three consecutive probes.
6. `/readyz.revision` exactly matches `deployed_sha` on those probes.
7. Public, authenticated, admin, and reversible mutation Playwright projects all pass.

Only then does GitHub record commit status:

```text
preview/promotion-eligibility = success
```

While the gate is running, the same status context is `pending`. If any eligibility condition fails, the final state is `failure`.

## GitHub permissions

The Preview regression workflow has only:

```yaml
permissions:
  contents: read
  statuses: write
```

`statuses: write` is required solely to bind the promotion result to the deployed commit SHA. No deployment-write or contents-write permission is granted.

## Auto-deploy flow

```text
push fix/m12d8-reconcile-056-ui
  -> Coolify Preview deploy
  -> SOURCE_COMMIT = X
  -> post-deploy repository_dispatch(deployed_sha=X, branch=Preview branch, profile=full)
  -> preview/promotion-eligibility = pending on X
  -> revision-aware Full Gate
  -> preview/promotion-eligibility = success|failure on X
```

## Reusable eligibility check

Use:

```bash
pnpm preview:promotion:check <full-git-sha>
```

The checker reads the latest `preview/promotion-eligibility` commit status and prints:

```text
SHA=<sha>
CONTEXT=preview/promotion-eligibility
STATE=success|failure|pending|missing
PROMOTABLE=yes|no
TARGET_URL=<gate run when available>
```

It exits 0 only when `PROMOTABLE=yes`. This command is intended to become a mandatory preflight in M12D.9 before any controlled Production promotion.

## Safety boundaries

- This milestone does not deploy or mutate Production.
- `ipenovel-prod` remains Manual deployments only.
- Manual `workflow_dispatch` can still run diagnostics, but it does not create promotion eligibility because eligibility is reserved for post-deploy `repository_dispatch` runs.
- A public-only gate can never mark a SHA promotion-eligible.
- A dispatch from any branch other than the dedicated Preview branch fails automated gating and cannot become eligible.

## Activation verification

The milestone is complete only after one real push to the configured Preview branch proves this sequence without manual redeploy:

1. GitHub push is accepted.
2. Coolify auto-deploys the new Preview SHA.
3. `/readyz.revision` changes to that SHA.
4. Coolify emits `preview-deployed` automatically.
5. GitHub records `preview/promotion-eligibility=pending` on that SHA.
6. Revision-aware Full Gate passes 8/8.
7. GitHub records `preview/promotion-eligibility=success` on the same SHA.
8. `pnpm preview:promotion:check <sha>` returns `PROMOTABLE=yes`.
