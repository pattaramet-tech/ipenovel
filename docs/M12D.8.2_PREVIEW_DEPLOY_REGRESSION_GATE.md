# M12D.8.2 — Preview Deploy Regression Gate

## Objective

Turn the M12D.8.x Playwright harness into a repeatable post-deploy gate for the dedicated Preview environment.
This milestone does not change application business logic, production routing, checkout/payment behavior, or production data.

## Safety model

- The deploy gate accepts only `https://r2-preview.ipenovel.com`.
- Any other hostname, including the production domain, is rejected before browser tests start.
- The workflow is not triggered directly by `push`; a push can occur before Coolify finishes replacing the Preview container.
- The supported automatic trigger is `repository_dispatch` with event type `preview-deployed`, emitted only after the deploy system has completed its Preview deployment.
- `workflow_dispatch` remains available for a controlled manual run.
- The gate waits for both `/healthz` and `/readyz` to pass three consecutive probes before Playwright starts.
- Public tests are read-only.
- Admin tests are read-only.
- The only mutation test is the reversible package cart regression; it removes its cart change in `finally`.
- Checkout, wallet payment, slip upload, publishing mutations, and production are outside this gate.

## Gate profiles

### `public`

Runs the public Playwright project only. It requires no account secret and is suitable as the minimum post-deploy Preview gate.

### `auto`

Runs public and then uses any locally available user/admin storage states. Mutation is still opt-in with `E2E_ALLOW_MUTATION=1`.
This profile is useful for local diagnostics, not as the strict CI promotion gate.

### `full`

Requires both user and admin Playwright storage states. It runs, in order:

1. public
2. authenticated user
3. admin/workspace read-only
4. reversible package Add-to-Cart mutation

Missing user/admin state fails the gate instead of silently skipping coverage.

## Local command

With the ignored Preview user/admin states already captured:

```powershell
$env:E2E_GATE_PROFILE="full"
pnpm test:e2e:preview-gate
Remove-Item Env:E2E_GATE_PROFILE
```

The current local M12D.8.2 verification completed all eight Playwright checks successfully.

## GitHub Actions workflow

Workflow: `.github/workflows/preview-regression.yml`

Supported events:

- `workflow_dispatch` — choose `public` or `full` manually.
- `repository_dispatch` with event type `preview-deployed` — intended for the Coolify post-deploy hook.

The workflow installs dependencies and Chromium, typechecks the Playwright harness, waits for Preview readiness through the gate runner, and uploads Playwright report/trace/screenshot/video artifacts only when the run fails.

## CI authenticated-state secrets

Full CI requires these GitHub Actions secrets:

- `E2E_PREVIEW_USER_STORAGE_STATE_B64`
- `E2E_PREVIEW_ADMIN_STORAGE_STATE_B64`

Each value is the base64 encoding of the corresponding Playwright `storageState` JSON. The gate decodes them only on the ephemeral Actions runner into the already-ignored `.playwright/.auth/` directory.

Do not commit storage-state JSON, cookies, OAuth credentials, passwords, or decoded secret values.
Use dedicated Preview test accounts and rotate/re-capture state when the session expires.

Secret provisioning is intentionally separate from repository code changes because transferring an authenticated session to GitHub is a security-sensitive account operation.

## Coolify activation contract

After the Preview deployment is confirmed successful, the deploy system should emit a GitHub repository dispatch with:

```json
{
  "event_type": "preview-deployed",
  "client_payload": {
    "profile": "public",
    "deployed_sha": "<Coolify SOURCE_COMMIT>"
  }
}
```

Use `"profile": "full"` only after both authenticated-state secrets have been provisioned.

The Coolify/GitHub dispatch credential must be stored in the deploy platform secret store and must never be placed in this repository or application environment visible to browser code.

## Promotion policy

Minimum safe activation:

`Preview deploy complete -> repository_dispatch(preview-deployed/public + deployed_sha) -> readiness + revision stable -> public Playwright PASS`

Strict promotion gate after CI secret provisioning:

`Preview deploy complete -> repository_dispatch(preview-deployed/full + deployed_sha) -> readiness + revision stable -> public + auth + admin + mutation PASS`

A failed or timed-out gate blocks promotion. It does not roll back or mutate Production automatically.

## Revision-aware hardening

M12D.8.3 supersedes the original readiness-only limitation. `/readyz` now exposes a validated deployment revision from Coolify's runtime `SOURCE_COMMIT`, and repository-dispatch runs must provide `client_payload.deployed_sha`. The gate waits until health/readiness are good **and** the observed revision matches the dispatched revision for three consecutive probes before starting Playwright.

> GitHub activation note: `repository_dispatch` and the manual Actions UI become operational only after this workflow file exists on the repository default branch. Keeping the implementation on a feature branch is safe for review/local verification but does not activate the remote gate yet.
