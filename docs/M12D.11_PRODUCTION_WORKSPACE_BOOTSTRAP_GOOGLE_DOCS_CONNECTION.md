# M12D.11 — Production Workspace Bootstrap + Google Docs Connection Activation

## Scope

M12D.11 closes the first-run gap discovered after `main@4572cc5` reached Production:

- a clean Production database has no Workspace rows, but the Workspace creation form was permanently hidden;
- Workspace Google Docs connections are user-owned records and Production correctly has none from staging;
- the read-side connection list existed, but no Production UI/HTTP flow could create a durable Google Docs connection.

No staging Workspace rows, refresh credentials, or encryption keys are copied into Production.

## Workspace first-run bootstrap

`/workspace` now exposes the existing `workspace.create` mutation only while there are no active workspaces. The existing mutation success path selects the newly-created Workspace and refetches the list, so a fresh Production database can bootstrap itself without direct SQL or seed data.

Once any active Workspace exists, the compact selector remains the normal UI and the first-run creation card is hidden again.

## Google Docs connection flow

The Editorial Workspace exposes **เชื่อม Google Docs**, which starts:

```text
GET /api/workspace/google/start
→ authenticate current session
→ re-check platform admin in DB
→ create one-time server-side PKCE/state attempt
→ Google consent (openid + read-only Drive metadata + Docs)
→ GET /api/workspace/google/callback
→ authenticate the same current admin
→ consume one-time state/verifier
→ exchange authorization code using the fixed configured callback
→ verify returned read-only scopes
→ resolve Google's stable subject through OIDC userinfo
→ AES-256-GCM encrypt the refresh token
→ upsert workspaceGoogleConnections for that admin + Google subject
→ redirect /workspace?googleDocsConnect=success
```

The Workspace OAuth flow is independent of `AUTH_PROVIDER`; it may be used while ordinary sign-in remains on Manus.

## Runtime configuration

Both Production staging and Production need the existing server-only:

```text
GOOGLE_OAUTH_CLIENT_ID
GOOGLE_OAUTH_CLIENT_SECRET
```

and these Workspace-specific variables:

```text
WORKSPACE_GOOGLE_DOCS_REDIRECT_URI
WORKSPACE_GOOGLE_DOCS_TOKEN_ENCRYPTION_KEY
```

Exact redirect URIs:

```text
Production staging:
https://production-staging.ipenovel.com/api/workspace/google/callback

Production:
https://ipenovel.com/api/workspace/google/callback
```

Both exact URLs must be registered as Authorized redirect URIs in the Google Cloud OAuth client.

`WORKSPACE_GOOGLE_DOCS_TOKEN_ENCRYPTION_KEY` must decode to exactly 32 bytes. Generate a different key for each environment and store it only in the runtime secret store. Never migrate connection rows or ciphertext between environments.

## Security invariants

- start/callback require a valid current session and platform-admin authorization;
- state and PKCE verifier are server-side, one-time, user-bound records;
- callback URI is an explicit environment value and is never derived from Host / Origin / forwarded headers;
- Production requires HTTPS and the exact `/api/workspace/google/callback` path with no query/hash;
- returned scopes must include `drive.metadata.readonly` and `documents.readonly`;
- `openid` is requested only to obtain Google's stable `sub` identity;
- access tokens are transient and never stored;
- refresh tokens are encrypted before persistence and never logged;
- callback destinations are fixed internal paths; no `returnTo` or open redirect input exists.

## Verification before Production promotion

1. Run targeted M12D.11 unit/static tests.
2. Run `pnpm check`.
3. Run `pnpm build`.
4. Run `pnpm test:gate`; no new failures are allowed.
5. Deploy candidate to `ipenovel-production-staging` with the staging callback and a staging-only encryption key.
6. On staging, create a Workspace from an empty Workspace set (or an isolated clean test tenant), reload, and confirm it persists.
7. Connect Google Docs, confirm the connection is `active` + `scopeReady`, then Quick Import one read-only Google Doc.
8. Run isolated Production staging Full Gate.
9. Create a fresh Production Promotion authorization for the exact candidate SHA.
10. Only then pin and manually deploy `ipenovel-prod`.

M12D.11 is complete only after the Production post-deploy smoke proves first-run Workspace creation and Google Docs connect/import work without cross-environment data copying.
