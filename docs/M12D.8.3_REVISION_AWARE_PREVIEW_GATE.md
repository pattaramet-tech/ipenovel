# M12D.8.3 — Revision-Aware Preview Gate Hardening

## Objective

Ensure the post-deploy regression gate tests the exact Preview revision that Coolify just deployed, not merely any healthy container currently answering `r2-preview.ipenovel.com`.

## Runtime revision source

Coolify exposes the deployed Git commit as the predefined runtime variable `SOURCE_COMMIT`.
`/readyz` may expose only this value after strict Git-SHA validation; arbitrary environment text is never reflected.

Successful readiness response with a valid revision:

```json
{
  "status": "ready",
  "revision": "c9fa5724c39a66da481d1e43998ea455d29504c3"
}
```

If `SOURCE_COMMIT` is missing or invalid, readiness remains backward-compatible:

```json
{ "status": "ready" }
```

## Gate contract

`repository_dispatch` must send the exact Coolify runtime revision as `client_payload.deployed_sha`.
GitHub Actions maps that value to `E2E_EXPECTED_REVISION` and enables `E2E_REQUIRE_EXPECTED_REVISION=1` for repository-dispatch runs.

The gate requires three consecutive probes where all conditions are true:

1. `/healthz` returns HTTP 200 and `status=ok`.
2. `/readyz` returns HTTP 200 and `status=ready`.
3. `/readyz.revision` exactly matches `E2E_EXPECTED_REVISION` after case normalization.

Any mismatch resets the stability counter. A timeout fails before Playwright starts.

Manual `workflow_dispatch` remains backward-compatible: revision enforcement is optional so operators can use the workflow for diagnostics or recovery.

## Coolify post-deploy payload

The Preview post-deployment command must dispatch:

```json
{
  "event_type": "preview-deployed",
  "client_payload": {
    "profile": "full",
    "deployed_sha": "<SOURCE_COMMIT>",
    "branch": "<COOLIFY_BRANCH>"
  }
}
```

Production is outside this milestone and must not receive this hook.

## Activation sequence

1. Merge this milestone to `main` so the workflow understands `deployed_sha`.
2. Update only `ipenovel-preview` Post-deployment command to include `SOURCE_COMMIT`.
3. Port the M12D.8.3 commit onto the actual Preview deployment branch.
4. Redeploy Preview.
5. Confirm the automated `preview-deployed` GitHub Actions run reports the same expected and observed revision.
6. Confirm public + auth + admin + mutation regression passes.

## Failure semantics

- Missing `deployed_sha` on repository dispatch: fail-fast before network probes.
- Invalid expected SHA: fail-fast.
- Healthy old container with wrong revision: wait; never start Playwright.
- Revision never converges before timeout: fail the gate.
- Manual workflow without expected revision: readiness-only compatibility mode.
